# 公开对话链路与产品约定的统一修复

本轮承接已合入的 Codex 公开对话重写，检查共享核心以及 Codex、Kimi、Claude
适配器是否遵守同一产品约定。Grok 仅作为独立审查者，不新增 Grok 产品适配。

## 固定行为及代码归属

| 用户期待 | 实现归属 | 本轮修复 |
| --- | --- | --- |
| 一次授权持续有效 | 共享核心的配置转换和写锁 | 相同策略再次启用不写文件、不改变授权版本；重启、升级和新任务复用授权；用户关闭或调整范围才形成新边界 |
| 公开正文不丢失 | 每个客户端的正式 transcript 解析器 | 按原生格式选择用户输入、公开说明、最终回答；排除工具和隐藏推理；分页可以停在消息之间，不能截断消息 |
| 脱敏后直接可用 | 共享核心的扫描、存储和导出 | 正文不调用模型；保存与游标一起提交；扫描器暂时失败保留待处理记录，恢复后无需新 Stop |
| 摘要不拖住业务 | 独立的摘要执行线程 | 只接收已脱敏正文，只能返回标题和摘要；慢、失败、撤销和过期结果都不能阻塞或覆盖新正文 |
| 用户不配置摘要模型 | 适配器的安装和升级 | Codex 内部固定 GPT-6-Luna/low；Kimi 内部固定 K3、关闭 thinking；Claude 复用原生提供方并请求低推理；模型策略后续由代码维护 |
| 重复启用无副作用 | 同一核心算法，适配器只调用 | 不再由三个安装器分别生成授权版本；缺失配置仍可初始化，损坏配置报告问题，不冒充首次安装覆盖 |
| 后台不弹窗、不留失控子进程 | 平台启动器 | Windows 子进程隐藏运行，用 Job 约束后代；命令允许合法空参数；协议和配置显式使用 UTF-8 |

移除了当前公开采集链路的正文、原生记录、Hook/MCP 入参和配置文件任意大小上限，
以及标题、摘要、front matter 和路径的额外产品层上限。摘要读完整脱敏正文；不再取首尾冒充全文。
Kimi 的大输入通过临时 agent 文件传递，Claude/Codex 使用 stdin，避免命令行长度变成内容上限。

仍保留有实际边界含义的控制：无效数据、授权和来源校验、取消、进程超时、并发容量、
查询分页及 Git 普通文件的 100 MiB 平台限制。旧版模型正文整理仅供旧安装兼容，
当前三个适配器安装和升级都进入公开正文路径；旧的待应用模型结果不能在新路径执行。

## 测试如何对应问题

测试数量不作为产品可用的结论。每层的检查结果都有明确范围：

1. 正式格式解析器：三个客户端分别验证消息选择、时间边界、续读和大消息。
2. 完整采集：正式解析器、真实 Gitleaks、数据库和导出器一起检查 129 KiB、1 MiB、10 MiB 的公开内容。
3. 入口进程：Codex 的真实 Stop 和 MCP 子进程接收大输入；连续请求不能因上一条较大而断开。
4. 状态变化：重复启用、关闭再启用、扫描器恢复、摘要慢和旧结果返回分别有可观察的存储断言。
5. 平台差异：Windows 原生编码与 WSL 分别运行；Claude 新增 Windows CI；独立虚拟环境检查依赖的实际 Git 提交。
6. 原生模型：Codex 真实内部摘要 worker 在两个系统运行；模拟文本明确标为模拟，不把摘要中的说法当成独立事实。
7. 真实 NPU、公开发布和再次检索：沿用[上一轮已完成的验收证据](codex-public-transcript-acceptance-2026-09-29.md)，不把本轮组件回归说成重跑了远端硬件。

Kimi CI 去掉已被全量发现覆盖的重复组件步骤，保留独立的原生启动检查。
Claude 不再对同一开发分支同时运行 push 和 PR 两套矩阵；三个适配器取消被新提交替代的旧检查。
核心的 Python 3.11 与跨系统 Python 3.13 验证属于不同兼容维度，保留。

首次托管 Codex CI 在 Windows 和 Linux 分别拦住生命周期问题，失败日志保留：
启动期间用“尝试拿锁”观察锁状态会与服务争抢所有权；短期更新仓库可能在 Git fetch
结束后仍有自动维护写入。核心现在使用已有启动预算等待短暂锁观察者，测试先等服务响应
再核验锁；更新器 fetch 关闭自动后台维护。新增反例在旧核心上稳定失败，在修复后通过。
后续 CI 又定位到一次性 Git 源仓库的 `.git` 清理竞态，因此该测试夹具在第一次 commit
前也关闭自动维护；产品更新器和测试源仓库分别管理自己的后台工作。
没有通过扩大清理重试或仅重跑失败用例掩盖原因。

Claude 的真实本地 VCS 安装测试还复现了浅克隆被 pip 再次按部分克隆读取时，Git
反复派生子进程的问题。CI 为这份安装夹具获取完整历史；夹具在 pip 前拒绝浅克隆，
并用既有进程组/Windows Job 管理安装进程树。安装保持离线、真实构建、真实
`direct_url.json`，没有用伪造元数据绕过版本核验。Python 3.11 上复现修复后，两项
安装边界检查约 12 秒通过，随后三系统 Claude CI 全部通过。

最终回归还暴露了两类旧测试假设：一处仍要求完整坏行让整篇正文失败；另一处要求
异步采集在第一次处理时就结束。前者改为通过真实 Stop 核对好消息、游标和坏行诊断；
后者启动真实后台循环，核对同一通知最终完整保存，不手工重发 Stop。原 CI 的 pending
记录没有打印具体原因，不能据此断言是调度还是扫描器瞬时失败。测试现在保留失败状态。

新增重复启用用例在 macOS 和 Windows CI 拦住了目录别名问题：锁内合并前字符串不同，
解析后却是同一目录。共享核心统一按真实路径去重，并忽略范围顺序变化；相同权限不重写
配置。补测使用 `..` 别名，Linux 也能稳定覆盖，不依赖某台机器恰好存在的系统符号链接。

| Codex | 全量 280 项含 5 跳过 | 最终固定版本 280 项含 11 跳过 |
| Kimi | 全量 246 项含 6 跳过；配置/授权相关 43 项通过 | 全量 246 项含 2 跳过；最终入口相关 27 项通过 |
| Claude | 159 项含 8 跳过 | 159 项含 1 跳过；最终入口相关 8 项通过 |
| Codex 摘要 worker | Luna/low，9.56 秒，返回 title/summary | Luna/low，16.08 秒，返回 title/summary |

这里的“项含跳过”不是通过数；平台跳过不当成成功。Windows 全量后有代码修改时明确记录相关补测，
不将较早全量结果冒充最终提交完整重跑。最终代码提交以关联 PR 的托管 CI 为准。
WSL 使用独立目录及虚拟环境，依赖按发布提交安装。
WSL 摘要初次运行缺少 CLI 路径及默认登录，复用既有验收 CLI 和已授权 profile 后成功；
没有要求用户重复登录，也没有修改全局配置。Kimi/Claude 原生模型端到端验收未在本轮执行。

## 独立审查与发布

真实 Grok 4.7 / xhigh 已完成第一轮七仓库审查，保留[原始审查报告](reviews/grok-product-contract-2026-09-29.md)
及其中的实测/静态/未覆盖边界。报告针对其表内固定快照，不表示后续修复仍有同样问题。

| 审查发现 | 处理 |
| --- | --- |
| 授权文件暂时损坏时重复启用会换代 | 核心区分故障与明确撤销；同一贡献选择也不重写文件；旧草稿和边界保留 |
| Hook 等待完整 JSON | 保留完整身份校验和宿主期限，拒绝凭半截路径开始采集；完整大对象已做进程测试；核心 CLI 的旧 128 KiB 门槛已移除 |
| 扫描器非零退出、坏报告不恢复 | 统一进入同一通知的自动重试；游标不先行，原始秘密不进入诊断 |
| 坏行拖住整个任务 | 三个正式解析器隔离单条坏记录并保存位置诊断，好消息照常继续；半写行仍等待补全 |
| Kimi 并发添加范围会覆盖 | 在同一个写锁内重读并合并；路径别名由核心统一去重 |
| Kimi 分叉状态暂不可读会收进父历史 | 等待原状态恢复；同一通知重放只包含子任务公开文字 |
| 摘要扫描失败、进程中断后永不恢复 | 同一正文版本延迟恢复，正文始终已保存；非法模型输出仍不循环调用 |
| Kimi 摘要继承 always_thinking/max | 隔离配置移除思考能力和强度继承，显式关闭 thinking；真实 Kimi 模型行为仍待原生验收 |
| 当前验收文档仍写旧模型或用户可配 | 当前文档统一为业务 Luna/max、内部摘要 Luna/low；历史记录明确标注历史范围 |

另修复了显式删除 fork 被旧文档合并回来的问题；适配器省略 fork/account 时则保留同目标
已保存的值。二者是不同用户意图，分别测试。正文通过规则选择和本地脱敏处理，模型只生成
标题和摘要，不再引入另一套正文整理流程。
